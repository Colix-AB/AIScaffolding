# Endpoint Security — The Non-Negotiable Bar

These rules are absolute. A change that breaks any of them does not get merged, no matter how small the diff or how loud the schedule pressure.

## 1. Authentication is default-deny

- **Every business endpoint enforces authentication, and the enforcement lives in one choke point** — a single middleware that every request passes through. Anonymous requests reach a controller **only** when the route is on that middleware's explicit allowlist.
- **Adding a route that should accept anonymous traffic is a deliberate edit to that allowlist, with a justification comment naming the requirement it serves.** If instead you add a path to a *bypass* list (the route's own router takes responsibility), wire the authentication middleware into that router and say so in the route file's header. **Do not invent a third option** — a route that is neither explicitly gated nor explicitly allowlisted is the exact hole this rule exists to close.
- **Never read the actor from the request body, path, query, or any client-controlled header.** The actor comes from the verified-credential object upstream middleware sets. Reading `req.body.user_id` or `x-user-id` to decide what the caller may do is a security bug.
- **The scope (tenant / organisation / owner) is read from the middleware-resolved value**, never from the request body or a path/query parameter the client supplied. A client-settable scope header is only ever a *hint* that must be validated against the credential.
- **Watch for a credential type that outlives its intended surface.** If one route family mints a token whose narrow claim is only checked by *that* family's middleware, the same token presented to another route family is unchecked — and long-lived. Check the claim wherever the credential can be presented, not only where it was issued.
- **A borrowed session moved to another origin meets every cookie that origin trusts.** When an impersonated or support session runs on a host, check each cookie the host honours, not only the token you hand it — an operator's own refresh cookie once still worked there.
- **A role above the scope does not override membership of the scope.** An organisation-level admin acting on one tenant (copying it, reading its contents, handing it out) must also be an active member of that tenant, re-checked inside the transaction. Otherwise an owner's deliberate removal of a colleague is bypassed and the tenant's contents reach the whole organisation. A past release shipped exactly this until a security audit caught it.
- Use the established libraries for password hashing, token signing, and crypto. **Never roll your own.** Signing secrets are required in every environment; the app refuses to boot in production without a real value (a dev fallback is a development convenience only).

## 2. Isolation goes all the way down

- **Every write MUST be scoped in the `where` clause** — not merely checked beforehand. A write keyed only by `id` silently mutates another tenant's row when the caller knows (or guesses) the id.
- Where a pre-check is genuinely needed instead, it must **include a null guard**: many ORMs' `update({ where: { id } })` runs regardless of whether the prior read returned anything.
- For nested resources, scope by the parent that carries the tenant (`{ id, table_id }`) — not by the child id alone.
- **A cross-scope probe returns 404, not 403.** A 403 confirms the foreign row exists.
- **Never mount a static-file handler on per-tenant content.** Serve user content through a gated handler that resolves each request against the file record, 404s soft-deleted or orphaned rows, and rejects path-traversal characters before touching the filesystem. Signed URLs, never raw paths.

## 3. Input handling

- All user input is validated and sanitised at the boundary. Nothing untrusted reaches the database, the filesystem, a shell, or an LLM prompt. Free text bound for Postgres refuses NUL bytes (and lone surrogates) with a 400 — Postgres rejects them, so an unchecked one is a 500.
- **Third-party authors' strings are untrusted input to every agent prompt**: plugin/extension names and descriptions, identifiers read from uploaded source, user-named tables. Render only values passing an identifier-shaped allowlist, cap each length, keep each on one line, and leave author prose out. Base trust on the record's owning scope, never on a parsed package name.
- **Bound the whole request, not each part.** A multipart route caps the total size of all files (from `Content-Length`, before staging anything or spending a one-time ticket), not only per file — twenty 5 GB files stage 100 GB before any quota check. Outbound work driven by an upload's contents is bounded too: count every fetch attempt, misses included, and cap the bytes gathered.
- **Addresses a user hands you to fetch** go through an SSRF-safe fetch on every redirect hop, and the cheap checks (count, name, rights, same-site) run first so a refused call fetches nothing. "Same site" is not the registrable domain alone: hosting suffixes put many owners under one domain, and IP literals have no registrable domain (a public-suffix library folds unrelated IPs together). Pin the list to the first host, widening to subdomains only when that host is itself the registrable domain. A new fetch joining a call shares that call's deadline.
- **SQL is always parameterised.** When a raw query is unavoidable (dynamic identifiers the ORM can't express), the dynamic fragment **must** come from a fixed allowlist defined in the same file — never from a request field.
- **Errors don't leak internals**: no stack traces, file paths, or SQL fragments in API responses. The global error handler returns a generic envelope for 500s; controllers attach a status for deliberate user-facing messages.
- **No hard-coded secrets, API keys, tokens, or credentials.** Configuration goes in environment variables; secrets in a secret manager ([`config-and-secrets`](../config-and-secrets/SKILL.md)).
- Dependencies are vetted and audited; no high/critical findings get past CI.

## 4. The pre-PR self-check

Before opening a PR that touches an endpoint, a router file, a service, or the schema, run through this checklist. Reviewers reject changes that haven't.

1. **Anonymous test.** Could a request with **no** credential and a **forged scope header** reach this controller and operate on someone else's data? If yes, the route is on the wrong list — either add it to the anonymous allowlist with a justification (and a per-resource public gate inside the controller), or gate the router explicitly. **The pinning test must reach the auth gate:** send a valid scope header against a scope every earlier gate admits, and assert the auth refusal's own code. A 400 for a missing header or a 4xx from an earlier lock proves nothing about authentication.
2. **Cross-scope id probe.** For every read/write the request performs: does the `where` clause include the scope? If a pre-check fetches the row first, does the code refuse the write when the pre-check returns nothing?
3. **Default-deny posture.** If you added a new router, did you decide explicitly who is allowed to call it, and wire the matching middleware in the route file's first lines? If you added a path to a bypass list, did you say in the comment which middleware now takes responsibility?
4. **Static + signed URLs.** Did you mount anything as static on scoped content? Don't.
5. **Token shapes.** Did you read the actor from anywhere other than the verified-credential object? Don't. Is any credential you introduced checked wherever it can be presented, not only where it was minted?
6. **Rate limiting and enumeration.** Is any newly-public endpoint (login, signup, password reset, public read) rate-limited, and does it avoid distinguishing "no such user" from "wrong password"?
7. **Rate-limit keys.** On a route that skips scope resolution, the scope value is whatever header the caller sent: a limiter keyed on it is bypassed by a random header per request, and aimed at a victim's id it drains their bucket. Key such routes on the authenticated user, prefix keys by kind so a user key never equals a scope key, and test that two random headers share one bucket. A read that scans a whole tenant gets its own per-tenant limiter even behind auth. A list that gains a free-text `q` is now called per keystroke — give it the search limiter its siblings use.
8. **Work that outlives the request.** A route that queues a job escapes the request deadline, and a per-user limiter does not bound a many-user tenant. Add a per-tenant limiter beside it, and keep queued work from taking every shared worker slot. If limiters are relaxed outside production, a test that must hit the cap sets production mode before loading the middleware.
9. **Impersonation.** A route that mints or reveals a credential that can outlive the session (API key, pairing code, provisioning token, OAuth secret or redirect URI, invite) refuses impersonated principals — every route that returns or sets it, not only the minting one. A route that reads the user's own private data (inbox, notifications, preferences) omits it under impersonation, because the token carries the user's id.
10. **Deferred authority.** Anything issued now and redeemed later on the issuer's rights (an invite with a role, a grant, a share link) re-checks those rights at redemption, in the same transaction, falling back to what the issuer can still grant — otherwise a demoted or removed issuer keeps granting.
11. **A new filter or query operator never widens a read.** A condition the server cannot answer is a 400, never silently dropped: dropping it reads every row, and bulk deletes often read through the same filter. For a list operator (`in`), refuse an empty list, a blank member, and a member the column cannot hold; normalise ids as for a single value. Client-side mocks answer the same way.
12. **Secrets out of stored drafts.** Anything persisted even when rejected (an agent's plan, a draft, an audit entry) strips secret values before **any** early exit — not only after every lookup succeeds. Judge secrecy by the target's declared type (including nested in objects and arrays), never by a field-name pattern.
13. **Limits and counters.** A change that removes or loosens a quota names what still bounds the resource (dropping a user cap left self-sign-up unbounded; dropping a job-count limit allowed unbounded every-second schedules). A change that gives a counter a consequence (a charge, a takedown) checks who can move it — counting anonymous requests once let a third party run up a victim's bill.
14. **Inline scripts and CSP.** An inline `<script>` runs only by its hash in every Content-Security-Policy that serves it. Changing the script re-pins the hash in **all** of them, or production blocks it. Add a new source (script, font, frame, API host) to the policy in the same PR, and take the list from a real browser run collecting `securitypolicyviolation` events — dependencies do things your own code never does.
15. **Browser storage.** `sessionStorage` is copied into a tab opened with `window.open`, a duplicated tab and a restored one. A stored session never stands in for a fresh handover: restore it only on that tab's own reload.
16. **Route inventories.** If the project keeps inventories of routes by audience (anonymous-account denials, agent-tool allowlists, account-creation sites), declare the new route there — such tests often run only in CI's backend selection, so run them by hand.

**Surfaces have shipped reachable to anonymous callers with a forged scope header because these steps were skipped. That cannot recur. If you have doubts about a specific endpoint, stop and ask before merging.**
